# Migrate error and diagnostic consumers

Use the public structured API from [ADR 0003](decisions/0003-structured-diagnostics.md), not the deferred redactor PR stack. The error contract keeps all 17 categories required by issue #7, operation identity, recovery choices and Codable transport. Error payloads contain no arbitrary strings.

## Preserve useful error messages

Construct `GuesthouseError` from a known cause and typed facts. Use `userMessage` and `recoveryActions` for error presentation, and `DiagnosticEvent.Outcome(error: error)` for diagnostics. That conversion maps confirmed `GuesthouseError.canceled` to the terminal `.canceled` outcome and other domain errors to `.operationFailed`; do not wrap cancellation directly as failure. A request to cancel is still `.cancellationRequested` until the execution layer confirms its outcome. Low-level execution failures can use `DiagnosticFailure`. Unknown errors must not attach an underlying `Error`, `localizedDescription`, command output, path or generic metadata dictionary.

The text of an error is generated by Guesthouse. It is not permission to forward raw stderr. A canceled or disconnected operation retains inspection-first recovery; a trust failure offers repair, never a bypass. General error recovery does not automatically replay mutations.

## Update existing call sites

| Previous payload | Replacement |
| --- | --- |
| `insufficientDisk(..., volumePath:)` | Keep required/available byte counts; omit the path |
| `downloadVerificationFailed(artifact:check:)` | Keep the verification check; omit arbitrary artifact text |
| `runtimeIncompatible(found:required:)` | `runtimeIncompatible`; show tool-version details only through a separately validated compatibility view |
| `unsupportedHost(.macOSTooOld(found:minimum:))` | `unsupportedHost(.macOSTooOld)` |
| `toolMismatch(tool:found:expected:)` | Use the closed `GuesthouseError.Tool` enum; do not copy CLI version strings |
| `xcodeComponentsIncomplete(missing:)` | `xcodeComponentsIncomplete`; offer component repair |
| `RedactedLine`, `SanitizedText`, sanitizer fallback | Typed events/errors; no drop-in raw-string constructor |
| `OperationID` | UUID wire shape is retained |

The error Core contract and structured event/export integration are implemented. The existing compatibility, runtime, XPC and GUI branches still need call-site migration and integration testing. Do not merge their old sanitizer ancestors to make them compile. Preserve reusable domain logic and tests while replacing the obsolete text boundary.

## Respect transport boundaries

Diagnostic JSON exports use schema version 2 for the new `operationFailed` outcome. No importer or XPC wire activation is introduced here. When migrating RuntimeEvent and its envelopes, allocate an explicit incompatible protocol version, update both endpoints, and retain admission/size/authentication checks. Do not interpret an unknown error/event enum as arbitrary text.

Runtime adapters may parse bounded temporary output for known operations; they must emit typed results rather than forward that buffer to logs. The GUI diagnostic store/export consumes only `DiagnosticEvent`. Authentication prompts have a separate temporary sign-in channel. The migration is complete only when those boundaries are tested in their owning components (#9, #21, #30).
