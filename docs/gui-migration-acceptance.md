# Retained GUI migration acceptance

Keep [#78](https://github.com/PicoMLX/Guesthouse/pull/78), [#79](https://github.com/PicoMLX/Guesthouse/pull/79) and [#81](https://github.com/PicoMLX/Guesthouse/pull/81) open as references. Their complete acceptance has not landed. This audit maps retained requirements to merged code and identifies work still needed under [#29](https://github.com/PicoMLX/Guesthouse/issues/29), [#30](https://github.com/PicoMLX/Guesthouse/issues/30) and [#32](https://github.com/PicoMLX/Guesthouse/issues/32). Follow [issue #48](https://github.com/PicoMLX/Guesthouse/issues/48) for subsequent integration.

The snapshot is main `a55e83e8`, October 2, 2026 UTC. Review inventory includes 71 threads on #78, 63 on #79 and 34 on #81, including 30 unresolved threads at inventory time and five standalone suggestions across comments/reviews. Every outer and nested comments page was read; no connection had another page. A historical owner reply or resolved ancestor thread does not establish current acceptance. The tables below include every unresolved inline finding and the standalone suggestions; they do not resolve or waive them.

The interpretation follows [MVP-PLAN.md](../MVP-PLAN.md) §§2–3/10–11, [ADR 0003](decisions/0003-structured-diagnostics.md) and [ADR 0004](decisions/0004-disposable-environments-persistent-work.md). Typed diagnostics replace raw-log consumers. Stop/Start retains the disk and task files. Unknown outcomes require actual inspection; an inventory omission, terminal event or cancellation acknowledgement cannot establish stopped state.

## Closure and subsequent work

Close a historical reference without merging only after all applicable retained behavior and tests map to reviewed **merged** replacements. Pending PRs, old resolved findings and this audit do not satisfy that condition. No reference is closed by this change.

First integrate the diagnostic attribution stack after owner merges, then complete recovered-operation observation/cancellation and dashboard Stop on actual runtime identity/reconciliation. Keep capability freshness (#187), native missing-target repair (#24/#76/#32), signed-XPC/provider prerequisites and human gate #35 separate. Reuse the existing app model, Quit consumer, ClientKit and runtime infrastructure. Do not add another operation runner or restore the raw sanitizer stack.

The underlying GUI suites are `AppScenesTests`, `AppModelCheckTests`, `AppModelStartTests`, `OperationPresentationTests`, `StartCancellationTests`, `QuitCoordinatorTests`, `SessionDiagnosticsTests`, `DiagnosticsSelectionTests` and `DiagnosticsExportWriterTests`. Package evidence is in `RuntimeEventStreamTests`, `DiagnosticLogTests` and `DiagnosticsExportBuilderTests`. Automated fixtures validate consumer behavior; they neither run a provider nor record hardware gates. See [ROADMAP.md](../ROADMAP.md) for their prerequisites and later epics.

Local validation of this audit: all 78 app tests pass; the exact backend-selection function executes and passes in Release with local `ENABLE_TESTABILITY=YES` (required by the shared scheme’s `@testable` suites), and restoring the historical preview override makes that assertion fail. The compiler command confirms Release has no DEBUG definition. Focused Core diagnostic/export suites pass 23 functions, and the ClientKit stream suite passes 19, both with warnings as errors. Zero Swift warnings. The documented local coverage-off override does not change the repository scheme or waive current-head Cloud. An initial Release attempt lacked testability; two initial function selections executed zero tests and are not passing test evidence.
