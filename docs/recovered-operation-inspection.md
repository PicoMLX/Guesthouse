# Inspect previously observed operations

Use **Check environment** when Guesthouse reports that a previously observed operation needs inspection. A failed check, disconnected session or missing saved card does not establish that the operation stopped. Start, new environment setup and Stop-before-Quit remain blocked while this obligation exists.

`AppModel` retains the actual `EnvironmentStatus.inFlightOperation` UUID and its environment identity separately from current status. This is an inspection obligation, not a claim that the operation is still running, cancellation authority or a saved job to resume. The current app model owns it across window closure; runtime restart recovery remains the runtime's responsibility.

Each explicit check queries the current inventory and every retained target, including an omitted card. A valid individual status can add an obligation even if another status query fails. Partial checks never publish readiness or clear obligations. Retired, canceled, foreign and malformed status responses cannot add or clear identities.

Only a complete current check can clear an obligation: the environment must be listed, its status must name no in-flight operation and its VM state must be inspected running or stopped. An uncertain or not-found state remains blocked. An unlisted target also remains blocked even if its status says running or stopped; saved metadata needs reconciliation or explicit repair before it is available as a managed environment. The producer's actual reconciliation is required by the status contract; constructing a status fixture does not implement it.

Inspection never cancels, stops or replays the recovered operation. Quit presents the retained operation's actual identity through its existing unknown-outcome failure, and force-stop is unavailable. The next valid observed operation for the same environment updates the retained identity while preserving the refusal of new work.

This implements a bounded GUI retention slice of [#29](https://github.com/PicoMLX/Guesthouse/issues/29) and [#32](https://github.com/PicoMLX/Guesthouse/issues/32), following [MVP-PLAN.md](../MVP-PLAN.md) §§2–3/10–11 and [ADR 0004](decisions/0004-disposable-environments-persistent-work.md). It does not finish recovered progress/cancellation, dashboard Stop, provider inventory/adoption, fork/restart recovery or the two native missing-target requirements on [#258](https://github.com/PicoMLX/Guesthouse/pull/258). Keep retained [#78](https://github.com/PicoMLX/Guesthouse/pull/78) and [#81](https://github.com/PicoMLX/Guesthouse/pull/81) open for their full acceptance. Production VM mutations remain disabled pending provider prerequisites.

`RecoveredOperationTests` exercises failed and partial reads, omitted cards, uncertain identity retention, successful listed inspection, stale/canceled/malformed responses and a changed actual operation. The first two functions fail against the earlier app model: four assertions reproduce forgotten inspection targets, newly permitted Start/Quit and lost operation attribution. Fake replies validate this GUI policy without launching a provider, signaling a process or recording a hardware gate. Run the app suite through the shared Guesthouse scheme; the package hook independently preserves the warning policy.
