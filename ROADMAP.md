## Scope rules for the studies

**Guest interaction (#188).** Prefer the existing supported SSH task/tool path. If it cannot operate the guest UI, briefly compare a narrowly scoped guest-local CLI/MCP helper with a guest desktop app using supported Remote; do not implement every alternative. Record the executing machine/account/session and test explicit wrong-host, wrong-guest/session and stale-target requests after reconnect using benign fixtures: the supported Guesthouse path must refuse or report unavailable before acting or capturing. An unchanged host marker is supporting evidence only. Record wider authority available through other tool configurations separately; refusal by this path does not prove global Codex containment. An unenforceable boundary requires an explicit owner decision, never an inferred pass. Use structured controls when available and screenshots for visual assertions; reacquire observations after human takeover. Optional locked-use support does not prove cold-boot readiness. A helper candidate such as [accessibility-cli](https://github.com/DioxusLabs/accessibility-cli) requires dependency, API, packaging, signature and SSH permission review before adoption.

**Release scope.** #188 must produce either a demonstrated interactive workflow or an explicit build/test-only v1 decision with GUI automation shown as unavailable. #42 incorporates that decision before its run. This is not permission to waive lifecycle, credential, GPU, local-integration or other existing proofs. If interactive verification is selected, the complete-path run repeats it and beta must test its failure/recovery cases.

**Study budget and decision owner.** Ronald Mannak owns #188's scope decision. Budget two engineer-days of investigation plus one human validation session of at most two hours, starting when the study's safe prerequisites are available. Record start, effort, observations and remaining uncertainties. At exhaustion, stop exploration and present a concrete build/test-only recommendation or a separately scoped extension for Ronald to choose; no automatic budget renewal, feature inclusion or fallback approval. A recorded build/test-only decision satisfies #42's interactive-scope input without requiring implementation of the other approaches. Lack of a decision remains visible rather than being called a pass.

**Capture, model transmission and artifacts.** Before the first study capture, limit observation to approved benign fixture apps/windows and disclose that screenshots, accessibility content and visible app data may be processed by the model even when never stored. Define sensitive-window handling before capture/transmission: exclude authentication, credential and unrelated windows, or require deliberate user involvement before proceeding; if the tool cannot enforce scope, refuse or report unavailable. Post-capture masking or export review is not a substitute. Production #46/#47 must agree the same scope, disclosure and permission-revocation behavior before observation, followed by a reviewed artifact schema: source revisions/dirty state, environment/tool tuple, target/destination and result, plus bounds, retention, user review and selected export. Manual evidence also follows the existing reviewed-evidence template. No raw-output logging, automatic support-bundle attachment, or generic string metadata extension to DiagnosticEvent. #30 remains structured diagnostics; #91 remains deferred.

**Networking (#189).** Use only operator-owned benign endpoints. Measure actual reachability, including gateway exceptions and console exposure, before making an isolation claim. Do not assume a particular network flag is sufficient or that Tart/Softnet is a Lume integration. Any proposed enforcement needs privilege/signing/installation/failure analysis and must not silently fall back to unrestricted traffic. Baseline research does not authorize firewall mutation or weaken #82's VNC/credential prerequisites.

**Task handoff (#190).** Supported Codex handoff matches saved repository projects and transfers Git state into destination worktrees. Inventory one repo first, then siblings, dirty/untracked/ignored files, integration files and artifact references using the #16-approved workflow. Define omissions and unsupported cases rather than promising atomic transfer. Ordinary SSH workspace use does not depend on handoff.

## Keep deferred

Keep persistent local disks and safe work export. Custom snapshot/NBD storage, cloud fleet scheduling, a custom Ethernet gateway, a video pipeline and embedded Simulator pane need measured justification. A persistent supervisor and separate Mac mini hosting remain distinct architectural milestones in MVP §12. Do not modify macOS privacy databases to remove setup clicks or silently enable privileged host software.

The legacy 28–46 engineer-day estimate is not a current Lume commitment. #42 must re-estimate the chosen provider, any helper/guest-desktop topology, required network enforcement and the production artifact work. Handoff is separate follow-on scope.
